- Oodle.framework is GPL-3 (ooz): native/Oodle/NOTICE.md.

GOAL
An iPhone app ("NX Builder") that runs fully on the phone, no Mac. The user picks prod.keys, title.keys,
game NSP/XCI etc. (as .zip or as individual files; NEVER a folder picker, it fails for this user),
and the app builds a per-game, unsigned IPA. The user signs and installs that IPA with FlareStore
(each game gets its own icon). The app also has an "IPAs" tab (list, share to FlareStore, rename, delete, import).
Based on seedds/nxnative (github.com/seedds/nxnative), which normally needs a Mac to build.
Repo: github.com/jakebway/nxnativeios (local clone was /home/claude/nxnativeios; upstream clone /home/claude/src/nxnative).

ARCHITECTURE (details in docs/DESIGN.md, README.md status checklist)
- App = SwiftUI (app/Sources: App, BuildEngine, BuildView, IPAsView, SettingsView, PythonBridge.h/.m) embedding
  CPython 3.15.2 (python.org iOS XCframework). Binary .so modules become frameworks + .fwork files
  (ci/install_python.py, PEP 730). Extra libs: lz4, capstone 5 (libcapstone framework via LIBCAPSTONE_PATH).
- Python side: phone/nxbuild/{app_entry.py, driver.py, assemble.py, shim.py, selftest.py}.
  shim.py replaces subprocess.Popen so upstream scripts run in-process (python scripts via runpy; nx_extract,
  dmsh_xlate, spirv-cross via frameworks; xcrun metal/metallib are MSL source passthrough; zstd via compression.zstd;
  multiprocessing pools -> thread pools). driver.py loads upstream scripts/build_ipa_from_nsp.py.
  assemble.py replaces dm/ios/tools/build_ipa.sh (shell + NXGame.framework + tables + romfs.img + msl + Info.plist + icons).
- Native frameworks (CI): NxTools.framework (NativeAOT C#: nx_extract_main, dmsh_xlate_main),
  SpirvCross.framework (spirv_cross_main), capstone.framework. Workflows: native.yml, pydeps.yml, phone-python.yml,
  proof.yml, shells.yml, app.yml.
- Game code without a compiler: tools/mkgameframework.py writes NXGame.framework (Mach-O dylib, pure Python, unsigned).
  patches/0001 makes main.m dlopen it; patches/0002 compiles MSL source shaders on device
  (newLibraryWithSource) because phones have no offline Metal compiler.
- Player shells (game-less engine per title profile) are built by shells.yml and uploaded to release "shells";
  the app workflow bundles all shell-*.zip. Default shells: 010015100B514000, 0100535012974000, 010014E00DB56000.
  Add more profiles as the user asks (about 159 profiles upstream; only games with a registered profile work in v1).
